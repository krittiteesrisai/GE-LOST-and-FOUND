# Campus Lost & Found

ระบบแจ้งของหายและของพบภายในมหาวิทยาลัย พัฒนาเป็นเว็บแอปพลิเคชัน (Web Application) เพื่อเป็นศูนย์กลางรวบรวมข้อมูลของหาย-ของพบ ลดปัญหาข้อมูลกระจัดกระจายตามกลุ่ม Facebook/LINE และช่วยลดระยะเวลาในการติดตามทรัพย์สินคืนสู่เจ้าของ

โปรเจกต์นี้เป็นส่วนหนึ่งของวิชา วิทยาการคอมพิวเตอร์ วิทยาลัยการคอมพิวเตอร์ (กลุ่มการเรียนที่ 17 กลุ่มย่อยที่ 7)

🔗 **เว็บไซต์ใช้งานจริง:** https://ge-lost-and-found.vercel.app

---

## ✨ ฟีเจอร์หลัก

- 📢 **แจ้งของหาย / แจ้งพบของ** — กรอกชื่อสิ่งของ หมวดหมู่ รายละเอียด สถานที่ วันเวลา ช่องทางติดต่อ พร้อมแนบรูปภาพ
- 🔍 **ค้นหาและกรองข้อมูล** — ค้นหาด้วยคำสำคัญ, กรองตามหมวดหมู่, กรองตามสถานที่, เรียงลำดับล่าสุด/เก่าสุด
- 🧩 **ระบบแนะนำรายการที่ตรงกัน (Matching Suggestion)** — เมื่อเปิดดูของหาย ระบบจะแนะนำของพบที่ใกล้เคียงกัน (และกลับกัน) โดยเทียบจากหมวดหมู่และคำสำคัญ
- 📊 **สถิติภาพรวม** — จำนวนของหาย/ของพบที่ยังไม่คืน และรายการที่ปิดสำเร็จแล้ว
- ✏️ **แก้ไข/ปิดประกาศ** — เจ้าของประกาศ (จำผ่านเบราว์เซอร์) หรือแอดมิน สามารถแก้ไขข้อมูลหรือปิดประกาศเมื่อได้รับของคืนแล้ว
- 🔗 **คัดลอกลิงก์ประกาศ** เพื่อส่งต่อในกลุ่ม LINE/Facebook ได้ทันที
- 🛠️ **หน้าจัดการสำหรับแอดมิน** — ดูรายการทั้งหมด เปลี่ยนสถานะ ลบข้อมูล (มี dialog ยืนยันก่อนลบ) และใส่บันทึกเพิ่มเติม (Admin Note)

## 🛠️ เทคโนโลยีที่ใช้

| ส่วนประกอบ | เทคโนโลยี |
|---|---|
| Frontend | React 19 + TypeScript + Vite |
| Styling | Tailwind CSS |
| ฐานข้อมูล | Firebase Firestore (Cloud NoSQL Database) |
| การจัดเก็บรูปภาพ | Base64 string ฝังในเอกสาร Firestore (ไม่ใช้ Firebase Storage) |
| Routing | React Router DOM |
| Icons | lucide-react |
| Deploy | Vercel |

> **หมายเหตุ:** โปรเจกต์นี้ตั้งใจไม่ใช้ Firebase Authentication และ Firebase Storage เพื่อให้ยังคงอยู่ในแพลนฟรี (Spark Plan) ของ Firebase ได้ทั้งหมด โดยไม่ต้องผูกบัตรเครดิต/เปิด Blaze Plan

## 🔑 การเข้าสู่ระบบแอดมิน

หน้า `/login` → เลือก "ผู้ดูแลระบบ (Admin)" → กรอกรหัสผ่าน

- **รหัสผ่านเริ่มต้น:** `admin`
- สามารถกำหนดรหัสผ่านเองได้ผ่าน environment variable `VITE_ADMIN_PASSWORD` (สร้างไฟล์ `.env` แล้วใส่ `VITE_ADMIN_PASSWORD=รหัสของคุณ`)

> ⚠️ ระบบนี้ตรวจสอบรหัสผ่านที่ฝั่ง client (ไม่มี Firebase Authentication จริง) เหมาะสำหรับใช้งานเป็น **Prototype/MVP สาธิตผลงาน** เท่านั้น ไม่แนะนำให้ใช้กับข้อมูลจริงที่ต้องการความปลอดภัยสูง

## 🗄️ ฐานข้อมูล (Firestore)

ข้อมูลทั้งหมดเก็บใน collection ชื่อ `items` โดยแต่ละเอกสารมีโครงสร้างประมาณนี้:

```ts
{
  type: 'lost' | 'found',
  title: string,
  category: string,
  description: string,
  location: string,
  currentLocation?: string,   // เฉพาะรายการประเภท 'found'
  date: string,
  contact: string,
  imageUrl?: string,          // base64 string ของรูปภาพ (บีบอัดแล้ว)
  status: 'active' | 'resolved',
  adminNote?: string,
  createdAt: Timestamp
}
```

กฎความปลอดภัย (`firestore.rules`) กำหนดให้:
- ทุกคนอ่านข้อมูลได้
- ทุกคนสร้างรายการใหม่ได้ แต่ต้องกรอกฟิลด์ที่จำเป็นครบและไม่เป็นค่าว่าง
- ทุกคนแก้ไข/ลบข้อมูลได้ (เนื่องจากระบบยืนยันตัวตนแอดมินทำงานฝั่ง client เท่านั้น)

## ⚠️ ข้อจำกัดที่ทราบอยู่แล้ว (Known Limitations)

เนื่องจากเป็น MVP/Prototype สำหรับการทดลองและสาธิตผลงาน (ระยะเวลาพัฒนา 45 วัน) จึงยังมีข้อจำกัดต่อไปนี้ ที่ตั้งใจไม่แก้ในเวอร์ชันนี้เพื่อประหยัดเวลาและงบประมาณ:

- **ไม่มีการตรวจสอบรูปแบบช่องทางติดต่อ (เบอร์โทร/อีเมล/LINE ID)** — ผู้ใช้สามารถกรอกข้อความใดก็ได้ในช่องนี้
- **ไม่มีระบบยืนยันตัวตนผู้ใช้ (User Authentication)** — ผู้แจ้งของหาย/พบของไม่ต้องสมัครสมาชิก ระบบจดจำ "เจ้าของโพสต์" ผ่าน `localStorage` ของเบราว์เซอร์เท่านั้น (หากล้างข้อมูลเบราว์เซอร์หรือเปลี่ยนอุปกรณ์ จะไม่สามารถแก้ไข/ปิดประกาศของตัวเองได้ ต้องให้แอดมินจัดการแทน)
- **รหัสผ่านแอดมินตรวจสอบที่ฝั่ง client** — ไม่ใช่ระบบ authentication ที่ปลอดภัยระดับ production
- **รูปภาพเก็บเป็น Base64 ในเอกสาร Firestore** — จำกัดขนาดไม่เกิน ~1MB ต่อเอกสาร (ระบบบีบอัดรูปให้อัตโนมัติก่อนบันทึก)
